# Retest: fixes from the 2026-11-11 validation walkthrough

Each item is a fix from the owner's walkthrough, with the bug number from that
list. Run them on a Release build of 035-debugger at 2b9964988 or later.

## Memory windows

- [ ] **1. Multiselect.** In Watches, Shift+Down and Ctrl+click select several
      watches; Delete, the menu's Remove, or the bar's new Delete button
      removes them all, and one Undo puts them all back. Automatic watches
      are left alone. Bookmarks and Data blocks take a multiselect too, and
      Delete removes every selected row.
- [ ] **2. Find colors.** In a Memory window's find, the other matches are dark
      yellow and the current one is the PC arrow's yellow.
- [ ] **3. Scrollbar marks.** While a find is open in Memory, Disassembly, the
      console or a list pane, the scrollbar is wide and has a mark for each
      match, the current one brighter; closing the find puts the scrollbar back.
- [ ] **4. Escape.** Escape closes a pane's find bar with the focus in the
      pane's list, not only in the find box.
- [ ] **13. Address box.** Double-click selects a word, and a drag selects
      text, in the Memory window's Address box, the Heat map's and the console's
      command line.
- [ ] **14. Heat.** A new Memory window has heat on.
- [ ] **15, 16. Find.** Memory's Find... opens the inline find bar; `"SYNTAX"`
      and `"ERR"` find Applesoft's messages in ROM; no find result goes to the
      console.
- [ ] **18. Menu.** The Memory window's context menu has the regrouped layout
      (Copy rows together, Go to rows together, Display and Last access
      submenus, no Undo or Redo).
- [ ] **19. Region labels.** "Slot 0: language card switches" and the other
      region labels start inside the first byte column, with a bit of the
      outline leading into the text.
- [ ] **42. Light theme heat.** In System light, the byte text is readable over
      every heat fill.
- [ ] **47. View after a state load.** Move around in the Memory window, then
      File > Save state and File > Load state without moving it in between.
      The view stays where it was. Note whether the machine was running and
      whether the debugger was in history. Not reproduced so far; capture the
      window before and after if the view moves.

## Disassembly and source

- [ ] **5. F10 down.** With F10 pressed down, steps run without the run and step
      buttons, the watches or the registers flashing.
- [ ] **7. Cut at the PC.** `F 6000,7 4C 04 60 2C A9 01 60`, `R PC 6000`, F11:
      the PC arrow is on a $6004 row, `BIT` is cut into a DB line, and the
      JMP's arrow points at $6004.
- [ ] **8. Ctrl+G.** Ctrl+G in a code view opens a box for an address and goes there;
      in a Memory window it focuses the Address box.
- [ ] **9. Instruction column.** After switching to a theme with a wider face,
      no instruction is cut off (`LDA (GBASL),Y` at $F80E).
- [ ] **10. Ctrl+hover.** With Ctrl down over a symbol that has a definition,
      the pointer is the link cursor.
- [ ] **11. Browse.** The source tab's "was not found" infobar has Browse...,
      which opens a file picker.
- [ ] **12. Go to definition.** In drop-test.a65, Ctrl+click `loop` on line 16
      goes to line 14.
- [ ] **20. Find after a write.** After `F 6000,9 A9 FF 20 A8 FC E8 4C 00 60`, a
      find for `6005` finds the INX.
- [ ] **25. PC marker with source.** Stopped at a source line breakpoint with
      source code turned on, the disassembly's PC row has the yellow arrow. Not
      yet checked on screen.

## Breakpoints

- [ ] **6. SYM.** `SYMUSER name !` removes a symbol, as `SYMUSER ! name` does.
- [ ] **21, 27. Don't break.** The dialog's Don't break with no log message
      counts hits without stopping; the Hit count column has "(don't break)".
- [ ] **22. Menu order.** A breakpoint row's menu is in Visual Studio's order,
      with Go to source code for a source line breakpoint.
- [ ] **23. Unload.** `SRC CLEAR`, and File > Unload symbol or debug file,
      unload the debug file.
- [ ] **24. Edit a source line breakpoint.** Settings... on a source line
      breakpoint opens the dialog on Source line, with its file and line.
- [ ] **26, 30. Disk events.** Every disk event has a verb; DOS 3.3 sector and
      ProDOS block take Read, Written or Either; the check box labels are
      reworded and 13-sector format is under Address prologue.
- [ ] **28, 29. Log tips.** A disk breakpoint's log message tip lists
      `DISK.ADDR.TRACK`, `DISK.ADDR.SECTOR` and `DISK.ADDR.VOLUME`.
- [ ] **31. Required fields.** The breakpoint dialog marks its required fields
      with a red `*` and has no "Optional" text; Casso Explorer's New disk dialog
      marks File name.
- [ ] **Groups (FR-409 to FR-416).** `BPGROUP Loop 0,2`, then in the pane: the
      ungrouped rows first, the Loop heading with its count, collapsing; a row's
      Add to breakpoint group, New group... and Remove from group; a heading's
      Enable all, Disable all, Rename group..., Ungroup and Delete group and its
      breakpoints; each undone in one step. Save and reopen the project, and
      the groups come back.

## History and reverse execution

- [ ] **32 to 35. SEEK.** `SEEK -5s` works after `LIVE`; `SEEK CYCLE` takes the
      Registers pane's cycle count with commas; `SEEK INSTR` works and `POS` is
      its alias; every SEEK and LIVE replies with the time, cycle and
      instruction it landed at.
- [ ] **36, 37. Progress.** Reverse continue's dialog reads "Running backward to
      the previous breakpoint", and its bar's fill stays inside the capsule at
      a few percent.
- [ ] **38, 40. Speed.** Reverse continue to a disk write a few seconds back
      takes a moment, not minutes; with no breakpoint that stops, it goes to
      the start of history at once.
- [ ] **39. Band tip.** The history band's time tip appears right at the
      current location.

## Console, scripts and channel

- [ ] **17. Replies.** An error or result from a pane's menu or button appears
      in an infobar over that pane, from a dialog in a message box, and never
      in the console.
- [ ] **41. Log messages.** `CassoCli debug --attach <pid> --script log-test.txt`
      prints each breakpoint log message after the line that ran, plain and
      with `--json`. In the GUI console the messages appear as they are written,
      once each. The GUI half is not yet checked.
- [ ] **43. RUN.** A script run with RUN waits at each G for the stop before its
      next line.
- [ ] **MCP.** `breakpoint_messages` returns the messages in `data.messages`.

## Themes

- [ ] **44, 45. Preview.** Walking Tools > Theme, an open menu is drawn in the
      face it opened in, with the previewed theme's colors; closing the menu
      without a choice puts every pane back in the committed theme.

## State loads

- [ ] **46, 48. Breakpoints after a load.** After File > Load state of a state
      saved a moment before, the breakpoints are set, and the call stack's note reads
      "(state loaded at $XXXX)".
